# 5. Closed-Loop Control through a Spiking Motoneuron Pool

This exercise adds a biologically grounded layer on top of the muscle-actuated controller. Instead of sending the desired muscle force directly to the actuators, the controller drives a **pool of spiking motoneurons** (leaky integrate-and-fire neurons). The pooled, low-pass-filtered spike activity becomes the muscle activation. This mirrors how the nervous system produces force: through populations of motor units firing at modulated rates.

## Objective

Drive the arm's end-effector toward an interactive Cartesian target, but with the muscle commands generated by a **motoneuron pool** rather than computed analytically. Each muscle is driven by `N_PER_MUSCLE` motoneurons whose collective spiking, smoothed over time, sets that muscle's activation.

The neural model is implemented in [`neuron_functions.py`](https://github.com/Balint-H/ssnr_sim/blob/main/SSNR2026/neuron_functions.py).

---

## The Shared Control Pipeline

The mechanical control front-end is identical to the previous exercise and produces a desired pulling force per muscle:

1. Read and **clip the mocap target** to the reachable workspace
2. Compute the end-effector Jacobian $J$ and task velocity $\dot{x} = J\dot{q}$
3. Apply the task-space PD law $F = K_p\,e_{pos} - K_d\,\dot{x}$ (with $K_p = 10$, $K_d = 0.3$)
4. Map to joint torque and clip: $\tau = \mathrm{clip}(J^\top F,\,-1,\,1)$
5. Resolve into tendon forces: $f_{tendon} = (J_{tendon}^\top)^{+}\tau$
6. Keep the pulling part: $F_{target} = -\min(0,\, f_{tendon})$

Up to $F_{target}$ everything matches exercise 4. The new material is what happens **after** $F_{target}$.


---

## The Neural Drive Layer

Instead of writing $F_{target}$ to `data.ctrl`, the controller routes it through a spiking pool in three stages.

**1. Force → input current.** `force_to_current` maps each muscle's desired force to a synaptic input current, clamped between `I_MIN` and `I_MAX`:

$$
I_{muscle} = \mathrm{force\_to\_current}(F_{target};\; F_{max}, I_{min}, I_{max})
$$

**2. Current → motoneuron pool.** The per-muscle current is distributed across that muscle's motoneurons through the `assignment` matrix, then each neuron is integrated as a **leaky integrate-and-fire (LIF)** unit with a refractory period:

$$
I_{neuron} = \text{assignment} \cdot I_{muscle},
\qquad
\tau_m \frac{dv}{dt} = -(v - E_L) + R\,I_{neuron}
$$

When $v$ crosses threshold the neuron emits a spike, resets, and is held inactive for the refractory window. `detect_spike_refractory_pool` performs this integration for the whole pool and returns the spike vector along with updated `v_state` and `last_spike`.

**3. Spikes → excitation → activation.** The spike trains are pooled back per muscle (`mu_mapping`) and low-pass filtered with time constant `TAU_EXC` to obtain a smooth excitation, which becomes the muscle activation command:

$$
E \leftarrow \mathrm{update\_excitation}(\text{spikes}, E, \text{mu\_mapping}, dt, \tau_{exc}),
\qquad
\text{ctrl} = \mathrm{clip}(E,\, 0,\, 1)
$$

---

## Signal Flow

$$
\text{target} \;\to\; F \;\to\; \tau \;\to\; f_{tendon} \;\to\; F_{target}
\;\to\;\to\; I_{neuron} \;\to\; \text{spikes} \;\to\; E \;\to\; \text{ctrl}
$$

The first half is deterministic biomechanics; the second half is a spiking population model.

---

## Pool State and Initialization

The pool's state persists across timesteps and is set up once in `load_callback`:

* `build_mu_mapping(n_muscles, N_PER_MUSCLE, drive_scale, seed)` builds `assignment` (distributes muscle drive to individual neurons, with `drive_scale` introducing per-neuron heterogeneity reminiscent of recruitment) and `mu_mapping` (pools neuron spikes back to muscles).
* `init_pool_state(n_neurons, n_muscles, el)` initializes the membrane potentials `v_state` (at the resting potential `el`), the `last_spike` times, and the excitation `E_state`.

With `N_PER_MUSCLE = 10`, a pool of `model.nu` muscles yields `10 × nu` motoneurons. These states are module-level globals because the LIF dynamics are recurrent: each step depends on the previous membrane voltages and spike history.

---

## Simulation Model

The arm is a rigid-body dynamical system governed by:

$$
M(q)\ddot{q} + C(q,\dot{q}) + g(q) = \tau
$$

with $\tau$ produced by the muscle forces. The muscle activations are now the output of the neural pool rather than the controller directly.

---

## Simulation Loop

At each timestep (~2 ms), MuJoCo:

1. Computes forward kinematics
2. Calls the control function — which now also advances the LIF pool by `dt`
3. Computes forward dynamics, including muscle activation dynamics and forces
4. Integrates the system state forward in time

Because the neural pool is integrated inside the callback, its timestep is tied to the physics timestep `model.opt.timestep`.

## Parameters

| Parameter      | Value      | Meaning                                              |
| -------------- | ---------- | ---------------------------------------------------- |
| `N_PER_MUSCLE` | 10         | Motoneurons per muscle                               |
| `F_MAX`        | 6.0        | Force scale used in the force→current map            |
| `I_MIN`,`I_MAX`| 1e-10, 7e-10 A | Input-current clamp range for the pool           |
| `DRIVE_SCALE`  | 0.14       | Per-neuron drive heterogeneity in `assignment`       |
| `TAU_EXC`      | 20 ms      | Excitation (activation) low-pass time constant       |
| `Kp`, `Kd`     | 10, 0.3    | Task-space proportional and derivative gains         |
| `DEFAULT_LIF`  | —          | LIF parameters (threshold, reset, `el`, refractory)  |

---

## System Variables

| Variable      | Description                                                   |
| ------------- | ------------------------------------------------------------- |
| `mocap_pos`   | Interactive target position (dragged by the user)             |
| `J`           | End-effector Jacobian, joint → task space                     |
| `ten_J`       | Tendon Jacobian (sparse), joint → tendon space                |
| `assignment`  | Muscle → motoneuron current distribution matrix               |
| `mu_mapping`  | Motoneuron → muscle pooling for spikes                        |
| `v_state`     | Per-neuron membrane potentials                                |
| `last_spike`  | Per-neuron last spike time (for the refractory period)        |
| `E_state`     | Per-muscle excitation (the smoothed neural drive)             |
| `ctrl`        | Muscle activation commands, range `[0, 1]`                    |

---

## Key Insights

* Muscle activation is generated by a **spiking motoneuron pool**, not computed in closed form
* `TAU_EXC` sets the trade-off between **smoothness** (less tremor) and **responsiveness** (less lag)
* Pool state is **recurrent** and must persist across timesteps
* The deterministic biomechanics and the stochastic-looking neural drive are cleanly separated at `F_target`
